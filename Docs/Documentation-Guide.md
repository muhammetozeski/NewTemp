# Documentation guide

Start at [the index](İçindekiler.md) and select the topic needed for the task. Read [the purpose](Documentation-Purpose.md) when extending this knowledge library.

Preserve project-specific knowledge that saves future investigation: parsing precedence, literal-content boundaries, allocation rules, configuration fallbacks, and portable output behavior. A new topic must answer a real project question; do not create empty categories or generic .NET tutorials.

Distinguish behavior observed in source from behavior actually exercised. Before documenting a method as verified, use an isolated example and record the applicable version and conditions. Never invent past tests, user approval, or permanent rules from a single request.

Write English, complete explanations with concrete inputs and outcomes. Keep one authoritative explanation and link from other pages. Use relative document links from the containing page; commands must state their working directory or use full paths.

Add new pages to the nearest index with a sentence explaining when to read them. Update existing topics when behavior changes instead of leaving competing descriptions. Check changed links and remove copied template names, stale claims, and redundant text before delivery.

Temporary outputs and experiments belong in a folder obtained from NewTemp, outside the source project. Reuse that folder for the same task and organize its contents by purpose. They are not documentation. A dated handover belongs in Walkthrough and should link to reusable knowledge in Docs.
