# Handover with selective reading

Read this whole guide on first adoption. Walkthrough alone aims to minimize tokens; this does not impose savings on development, tests, Docs, or user communication.

Use known context rather than researching history to fill a record. A meaningful result affecting later work gets a new Markdown file named with the actual local creation time and a descriptive topic: `yyyy.MM.dd HH.mm.ss - Topic and outcome.md`. Use Europe/Istanbul time. Never invent past events or replace code history with a file and commit inventory.

Each record briefly conveys the current project purpose and state, the observation that changed an approach, its result, and what the next developer should learn. A few connected paragraphs are normally enough. No empty forms, raw outputs, apologies, emotional commentary, or duplicate accounts. Link to detailed reusable methods in Docs. Unknown or unfinished work must stay distinguishable from verified outcomes.

Before reading content, select filenames: the newest context, the newest record containing `Accumulation` if one exists, and relevant later experiences. Search older filenames by topic only when a specific gap remains; check whether a newer record changes the lesson. Stop once purpose, current context, relevant decisions, and experiences are understood. Do not scan every record or Git history.

Write a new accumulation only when it materially reduces future reading. Preserve the useful earlier context and lessons, name its scope and final covered record, and leave source records intact. Do not accumulate merely because time passed or a file count was reached.

Correct disproved information in a new dated record that names the old topic, the observation, and the accurate outcome. A known old record may receive a short timestamped correction without separate research; never erase its historical wording. A once-valid state that changed later needs a validity explanation, not a claim that it was always wrong.

Check that a new filename enables selection, its current state matches known evidence, and its document links resolve. No new lesson means no new record.
